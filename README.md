# Бот уведомлений о поручениях

Бот читает Google Таблицу «Поручения» и отправляет каждому сотруднику его новые задачи в личный Telegram-чат. Бот обновляет поля уведомлений I:K, а после подтверждения администратором — статус задачи в F. Сам бот поручения не создаёт.

Таблица: https://docs.google.com/spreadsheets/*******************

## Что уже реализовано

- Проверка таблицы раз в 60 секунд, интервал настраивается.
- Одноразовые персональные приглашения на 24 часа.
- Проверка ID, полного ФИО и активности сотрудника.
- Постоянная SQLite-база привязок и истории отправок.
- Разделение длинных поручений с сохранением прогресса каждой части.
- Автоматический повтор после ограничения частоты Telegram.
- При неизвестном результате отправки повтор выполняется только по решению администратора.
- Команды администратора для приглашений, ошибок, повторов и смены аккаунтов.
- Восстановление после перезапуска, блокировка второго процесса с той же базой.

## 1. Создать Telegram-бота

Откройте официального @BotFather: https://t.me/BotFather. Отправьте `/newbot`, задайте название и имя бота. Сохраните выданный токен в `.env`; не публикуйте его и не отправляйте в переписки.

Бот использует long polling: входящий публичный адрес и открытие портов не нужны. Для этого бота не должно быть настроено webhook и не должен работать второй получатель Telegram-обновлений. Сервис требует исходящего HTTPS-доступа к Telegram и Google.

## 2. Настроить доступ к Google Таблице

Создайте технический проект в Google Cloud Console, включите Google Sheets API, создайте сервисный аккаунт и скачайте его JSON-ключ. Это техническое подключение к разрешённым Google Таблицам, Gmail и другие приложения Workspace не используются.

Сохраните ключ в `secrets/google-service-account.json`. В документе откройте «Настройки доступа» и добавьте адрес `client_email` из ключа как редактора. Аккаунт имеет доступ только к предоставленным ему документам; в программе используется Sheets scope.

В Google Таблицах откройте «Файл → Настройки» и установите часовой пояс Москвы: `Europe/Moscow`. Подпись МСК в уведомлениях и время отправки рассчитываются по этому правилу. Бот проверяет часовой пояс при работе и не отправляет задачи, если настройка другая.

Выделите колонки B, E и J листа «Задачи» и установите формат даты и времени, например `dd.mm.yyyy hh:mm`, для всей колонки. Это сохранит читаемый вид времени при добавлении задач за пределами первых 100 строк шаблона.

## 3. Подготовить запуск в Windows

Требуется Python 3.11 или новее. Откройте PowerShell в папке бота:

```powershell
./start.ps1 Setup
```

Если Python не доступен под именем `python`, можно указать полный путь:

```powershell
./start.ps1 Setup -PythonCommand 'C:/путь/к/python.exe'
```

Setup создаёт окружение, устанавливает зависимости и копирует `.env.example` в `.env`, сохраняя существующие настройки.

Заполните `.env`:

```text
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_ADMIN_IDS=ваш_числовой_Telegram_ID
```

ID таблицы уже указан. Несколько администраторов перечисляются через запятую. Запрос `/id` к запущенному боту покажет ваш Telegram ID. Для первого запуска поле администраторов можно оставить пустым: получить ID, остановить бот, записать ID и запустить снова. Команды управления без списка администраторов недоступны.

Проверка подключения, без отправки задач:

```powershell
./start.ps1 Check
```

Запуск:

```powershell
./start.ps1 Run
```

Остановка — Ctrl+C. На компьютере бот работает только пока запущен процесс и компьютер включён. Для постоянной работы используйте сервер.

После подготовки окружения можно запускать бота двойным щелчком по `Запустить бота.cmd`. Файл `Проверить подключение.cmd` выполняет проверку без отправки задач. Окно остаётся открытым, чтобы можно было прочитать результат. Перед запуском заполните `.env` и сохраните JSON-ключ в указанной папке.

## 4. Подключить сотрудников

На листе «Сотрудники» заполните по одной строке на человека. ID должен быть уникальным текстом, например `EMP001`; полное ФИО — «Иванов Сергей Александрович»; «Активен» — `Да`. Варианты обращения помогают GPT выбрать человека, но бот маршрутизирует строго по ID.

Напишите боту от администратора:

```text
/invite EMP001
```

Бот вернёт персональную ссылку. Передайте её этому сотруднику. Сотрудник открывает ссылку и нажимает «Запустить». Выбор чужого ФИО из списка отсутствует. В базе хранится хеш приглашения; новая ссылка отменяет предыдущую неиспользованную ссылку.

Создать первое приглашение можно и локально, при остановленном процессе:

```powershell
./.venv/Scripts/python.exe bot.py invite EMP001 --username ИмяВашегоБота
```

## 5. Проверить первое поручение

На листе «Задачи» заполните строку:

| Колонка | Пример |
|---|---|
| A — Номер задачи | 1 |
| B — Дата создания | Текущая дата и время как значение даты |
| C — Задача | Подготовить коммерческое предложение |
| D — ФИО | Полное ФИО точно как в справочнике |
| E — Дедлайн | Дата и время как значение даты, либо пусто |
| F — Статус задачи | Новая |
| G — ID сотрудника | EMP001 |
| H — Готова к отправке | Да, только после заполнения остальных полей |
| I:K | Оставить пустыми |

Задача должна прийти в течение двух циклов проверки при доступности сервисов. Сотрудник не обязан иметь аккаунт ChatGPT или доступ к общей таблице.

Номер задачи — постоянный уникальный номер, не формула номера строки. Не переиспользуйте его после удаления задачи. При нескольких строках с одним номером бот пропускает все эти строки и фиксирует предупреждение в журнале.

Дедлайн может отсутствовать: бот пишет «Срок не указан». Значение берётся в отображаемом формате таблицы, поэтому в колонке E должен быть формат даты и времени. Заголовки и порядок колонок должны соответствовать подготовленному шаблону. Бот меняет статус задачи на «Выполнена» только после подтверждения администратора; «Готова к отправке» самостоятельно не ставит.

Пустые строки не мешают обработке. Отменённые, выполненные и неготовые задачи не отправляются. Если сотрудник ещё не подключён, бот ставит «Сотрудник не подключён» и ждёт. Если имя, ID или активность не совпадают со справочником, ставится ошибка.

## Административные команды

| Команда | Действие |
|---|---|
| `/id` | Получить свой Telegram ID |
| `/invite EMP001` | Выдать приглашение |
| `/errors` | Последние ошибки отправки из базы |
| `/retry 1` | Разрешить повтор ошибки после проверки |
| `/sent 1` | Подтвердить неизвестный результат как успешную отправку |
| `/unbind EMP001` | Удалить привязку и все приглашения сотрудника |

`/errors` показывает ошибки уже поставленных в очередь отправок; ошибки незаполненных строк отображаются в таблице, сбои доступа к таблице — в журнале процесса.

Перед `/retry` при неопределённом результате проверьте с сотрудником, дошло ли сообщение. Если дошло целиком — используйте `/sent`, повторного сообщения не будет. Если точно не дошло — `/retry`. Для длинного поручения повтор продолжается с первой части, по которой нет сохранённого успешного ответа. Если эта часть фактически дошла при потере ответа, она может продублироваться.

При смене Telegram-аккаунта сотрудника выполните `/unbind`, затем `/invite`. Если часть длинной задачи уже была отправлена в старый аккаунт, бот не будет продолжать её в новом: требуется ручная проверка и согласованное доведение остатка поручения.

## Постоянная работа на сервере

### Bothost

Подготовлен отдельный архив `telegram-task-bot-bothost.zip`: исходники в корне, `bothost.json` указывает `main.py`, собственный Dockerfile запускает тот же файл. Секретов, локальной базы и окружения Python в архиве нет.

1. В профиле Bothost включите «Загрузка бота из архива». По документации сервиса она доступна на тарифах Базовый и Pro и пока работает на одной тестовой ноде. Если функция недоступна, используйте загрузку из Git-репозитория.
2. В «Мои боты» выберите «Загрузить из архива», загрузите подготовленный ZIP, укажите Python и главный файл `main.py`. Если есть настройка «Использовать собственный Dockerfile», включите её. Приложение работает и с автоматическим Python Dockerfile, запускающим `main.py`.
3. Передайте токен через настройки Bothost. Наш код читает `TELEGRAM_BOT_TOKEN`; проверьте, что эта переменная задана. Перенесите остальные значения из `.env.bothost.example` в переменные окружения панели. Это образец без токена, а не готовая конфигурация.
4. В файловом менеджере создайте папку `data/secrets` и загрузите туда JSON-ключ под именем `google-service-account.json`. В переменной `GOOGLE_APPLICATION_CREDENTIALS` должен быть путь `/app/data/secrets/google-service-account.json`. Не включайте ключ в ZIP или Git. Каталог `/app/data` сохраняется между обновлениями; его резервные копии будут содержать и ключ.
5. `BOT_DATABASE=/app/data/bot.sqlite3` сохраняет привязки и историю. Если сотрудники уже подключались локально, остановите локальный бот и перенесите согласованную копию его базы перед серверным запуском. Не запускайте две копии бота одновременно.
6. Проверьте подключение в терминале панели: `python main.py check`. Проверка не отправляет задачи. После успешной проверки запустите или перезапустите бот и проверьте сообщение о подключении в журнале.
7. После первого подключения сотрудника проверьте сохранность привязки после перезапуска. Перед обновлениями сохраняйте резервную копию `data` при остановленном боте.

Домен и webhook этому боту не требуются. Первый запуск без JSON-ключа завершится сообщением о недостающей конфигурации; после загрузки ключа и заполнения переменных нужен перезапуск.

Документация Bothost: [архив](https://bothost.ru/docs/upload-bot-archive), [переменные окружения](https://bothost.ru/docs/environment-variables), [постоянное хранилище](https://bothost.ru/docs/database-storage), [Dockerfile](https://bothost.ru/docs/custom-dockerfile).

### Docker Compose на собственном сервере

Подготовьте `.env`, JSON-ключ и папки `data` и `secrets` рядом с `compose.yaml`. Если на сервере установлен Docker с Compose:

```text
docker compose up -d --build
docker compose logs -f --tail=100
```

Контейнер перезапускается автоматически. Секреты подключаются только для чтения; SQLite сохраняется в `data`. Не запускайте несколько копий с разными базами против одной таблицы: это создаст независимые очереди и дубли. После изменения `.env` пересоздайте контейнер.

Резервируйте `data` и файл `.env` отдельно от публичного исходного кода. Для согласованной резервной копии остановите сервис, скопируйте каталог `data` целиком и запустите снова. Удаление базы приводит к потере привязок и истории. Задачи, уже помеченные «Отправлено» в таблице, бот после потери базы автоматически повторять не будет: потребуется подтверждение администратором.

## Ограничения первой версии

- Изменения уже отправленной задачи не рассылаются. Для нового поручения используйте новый номер.
- Статус «Отправлено» означает принятие сообщения Telegram, а не прочтение сотрудником.
- Нет кнопки «Принял» и напоминаний о дедлайне.
- Значения I:K принадлежат сервису. Ручная правка этих ячеек не отменяет запись в SQLite.
- Бот сверяет номер перед записью статуса, но Google Sheets не предоставляет атомарную запись строки по ID. Не сортируйте и не перемещайте строки одновременно с синхронизацией; для просмотра используйте фильтры. При обнаруженном перемещении запись откладывается. История в SQLite остаётся источником факта отправки.
- Предел чтения — MAX_ROWS (по умолчанию 10000). Если размер листа превышает предел, бот приостанавливает обработку; увеличьте настройку.
- Большой поток задач может увеличить задержку. Первая версия рассчитана на небольшую компанию, без нескольких параллельных отправителей.

## Проверки

```powershell
./start.ps1 Test
```

Автотесты проверяют отправку, перезапуск, защиту от повторов, приглашения, отмены, неподключённых сотрудников, ошибки, длинные тексты и ограничения доступа. Они используют подменённые Google/Telegram-сервисы. Живая интеграция проверяется отдельно через `Check` и одну тестовую задачу после настройки ключей.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api), [Google Sheets API](https://developers.google.com/workspace/sheets/api/guides/values), [сервисные аккаунты google-auth](https://google-auth.readthedocs.io/en/latest/reference/google.oauth2.service_account.html).


## Завершение и проверка задач

Сотрудник нажимает «✅ Сообщить о завершении задачи №…» под новым поручением. Для старых сообщений: `/start`, кнопка «✅ Сообщить о завершении задачи», затем номер; также работает `/done 12`. `/cancel` отменяет ввод номера.

Бот проверяет привязку аккаунта, исполнителя, активность и уникальность номера задачи. Администраторам из TELEGRAM_ADMIN_IDS приходит ФИО, номер и содержание с кнопками «Подтвердить выполнение задачи» и «Вернуть задачу». До решения статус остаётся прежним. Подтверждение записывает «Выполнена» в F и уведомляет сотрудника. Возврат сохраняет прежний статус и сообщает, что задача ещё не считается выполненной; после доработки можно подать новый отчёт.

Отчёты и решения сохраняются в существующей SQLite-базе. Старые кнопки и повторные нажатия не применяют решение повторно. Изменённые поручения и привязки требуют нового отчёта. При сбоях синхронизация и недоставленные уведомления повторяются автоматически; потеря ответа Telegram может привести к повторному уведомлению, но не к повторному решению. Не перемещайте строки одновременно с записью статуса: Google Sheets не поддерживает атомарную проверку строки по ID.
